## Highlights

- Fixed [#77](https://github.com/juntaki/mutantkit/issues/77): SwiftPM
  projects using `project.path` to point `--project-root` at a parent
  directory containing local `.package(path:)` siblings now build and test
  correctly inside the sandbox. `SwiftPackageMacOSAdapter`'s actual
  `swift build`/`swift test` invocations previously ignored
  `configuration.project.path` entirely, always running at the raw sandbox
  root — even though `project.path` is the documented mechanism for this
  exact scenario, and was already correctly honored by plan-time discovery
  (`SwiftPMLiveSourceResolution`) and `diagnose()`. Every affected run
  failed with a misleading `baselineMismatch`, indistinguishable from a
  real build regression. Fixed by resolving `project.path` at the point of
  every actual build/test invocation (`build(in:)`, `runTests(in:)`, plus
  four other call sites that bypass those two), while leaving the raw,
  unresolved sandbox root untouched wherever it is used purely for
  repo-relative path bookkeeping (coverage attribution, lowered mutant
  source placement) — so its shape continues to match the plan's own
  outer-root-relative paths.

## Upgrade impact

No config changes required. This is a pure bugfix: any `mutantkit.yml`
that previously failed every run with `baselineMismatch` due to a
`project.path` pointing at a subdirectory with local sibling dependencies
will now build and test at the correct location. Projects that don't set
`project.path` (the overwhelming majority) are completely unaffected — the
fix is a no-op whenever `project.path` is unset, empty, or `.`.

## Breaking changes

None.
